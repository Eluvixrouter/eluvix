# API Reference

Eluvix provides a unified, production-grade REST API. In addition to being a drop-in replacement for the OpenAI Chat Completions specification, Eluvix exposes programmatic control over dynamic routing configurations, active local hardware discovery, Docker engine containers, canvas topology presets, GPU compute worker serving, and telemetry.

---

## Base URL & Same-Port TLS Auto-Upgrade

Eluvix features **same-port dual-protocol demuxing on port 3588**:

- **HTTPS (Canonical)**: `https://127.0.0.1:3588/api/v1` (Encrypted TLS via local `mkcert` certificate)
- **HTTP on 3588 (NOT upgraded for API traffic)**: `http://127.0.0.1:3588/api/v1` is served directly over plain HTTP by design (`apps/nextjs/server.mjs`: the same-port HTTP handler serves `/api/` before the 308 branch). Only browser navigation to port 3588 gets the `HTTP/1.1 308` upgrade to HTTPS. **Never send an `Authorization` Bearer token to the `http://` API URL** — it will work, unencrypted. API clients must use the `https://` URL above.
- **HTTP Fallback Port**: `http://127.0.0.1:3580/api/v1` (Secondary loopback port; same rule — browser navigation is upgraded, `/api/*` is served directly over HTTP, as documented on the configurator page.)

### Authentication: Master Password & Named API Keys

Eluvix supports two authentication mechanisms:

1. **Master Admin Password**:
   Pass your master admin password (from `~/.config/eluvix/auth.json`) in the standard HTTP `Authorization` header:
   ```http
   Authorization: Bearer <ADMIN_PASSWORD>
   ```

2. **Named API Keys (`keys.json`)**:
   Eluvix supports user- and role-scoped Named API Keys stored in `~/.config/eluvix/keys.json`. Each key is tagged with a `userId`, an `origin` (`client`, `harness`, or `playground`), rate limits, and model access whitelists:
   ```json
   {
     "keys": [
       {
         "id": "key_dev_alice",
         "key": "elx_live_a1b2c3d4e5f6g7h8",
         "name": "Alice Dev Key",
         "userId": "alice",
         "origin": "client",
         "rateLimit": 120,
         "createdAt": "2026-10-21T00:00:00.000Z"
       },
       {
         "id": "key_harness_trueforge",
         "key": "elx_live_harness_trueforge_01",
         "name": "TrueForge Agent Runner",
         "userId": "agent_system",
         "origin": "harness",
         "rateLimit": 600,
         "createdAt": "2026-10-21T00:00:00.000Z"
       }
     ]
   }
   ```
   Provide the key in the request header (both OpenAI `Authorization: Bearer` and Anthropic `x-api-key` headers are supported across all `/api/v1/*` routes):
   ```http
   Authorization: Bearer elx_live_a1b2c3d4e5f6g7h8
   x-api-key: elx_live_a1b2c3d4e5f6g7h8
   ```
   When a Named API Key is used, its `userId` automatically scopes the **Memory & Context Engine** (`viking://user/{userId}/memories`) and stateful `/api/v1/responses` records, and its `origin` activates the **Loop Guard** if tagged as `origin: "harness"`.

## 1. Chat Completions

### `POST /api/v1/chat/completions`

Executes an intelligent chat completion through the Switchyard pipeline. Supports both non-streaming JSON responses and Server-Sent Events (SSE) streaming.

#### Headers
```http
Content-Type: application/json
Authorization: Bearer <ADMIN_PASSWORD_OR_NAMED_KEY>
```

#### Optional Context, Silicon & Fabric Policy Headers
- `X-Eluvix-User`: Override user identifier for memory recall (if not using a named key).
- `X-Eluvix-Session`: Session identifier for multi-turn conversational memory tracking.
- `X-Eluvix-Hops`: Current hop count when chained through agent harnesses (used by Loop Guard).
- `X-Eluvix-Confidential`: Per-request confidential silicon policy override (`prefer-tee`, `require-tee`, `require-dual-attestation`).
- `X-Eluvix-Quantization`: Per-request quantization policy override (`prefer-nvfp4-hadamard`, `lossless-reasoning`).
- `X-Eluvix-Fabric`: Per-request Clos fabric policy override (`prefer-rail-optimized`, `require-collision-free-fabric`).
- `X-Eluvix-PD-Role`: Per-request disaggregation role preference (`prefill`, `decode`, `disaggregated-conductor`).
- `X-Eluvix-Effort`: Reasoning effort hint (`low`, `medium`, `high`).

#### Request Parameters

| Parameter | Type | Required | Default | Description |
| :--- | :--- | :--- | :--- | :--- |
| `model` | `string` | **Yes** | `"auto"` | Target model name or `"auto"` to trigger dynamic complexity, code escalation, and multimodal vision routing. |
| `messages` | `array` | **Yes** | — | Array of message objects (`role`, `content`). Content can be string or structured multimodal blocks (`image_url`). |
| `stream` | `boolean` | No | `false` | When `true`, streams completion tokens as standard SSE `data: {...}\n\n` chunks. |
| `temperature` | `number` | No | `0.7` | Sampling temperature between `0.0` and `2.0`. |
| `max_tokens` | `number` | No | — | Maximum token limit for generated output. |

#### Response Headers
- `X-Eluvix-Upstream`: The upstream ID that executed the request (e.g. `ollama-local`, `vllm-dlb-oooddp-moe`, `openai-cloud`).
- `X-Eluvix-Complexity`: Numeric complexity score assigned by Switchyard (`1`–`4`).
- `X-Eluvix-Cache`: Returns `HIT` if served from the semantic response cache, or `MISS` if executed upstream.
- `X-Eluvix-Memory`: Active context memory provider (e.g. `openviking`, `graphiti`, `lightrag`, `mem0`, `sqlite`, or `none`).
- `X-Eluvix-Memory-Tokens`: Number of memory context tokens prepended to the prompt.
- `X-Eluvix-Knowledge`: Active static knowledge base RAG status (`injected`, `empty`, `disabled`).
- `X-Eluvix-TTFT-Ms`: Time to First Token (Prefill latency in milliseconds).
- `X-Eluvix-ITL-Ms`: Inter-Token Latency (Decode step duration in milliseconds per token).
- `X-Eluvix-KV-Cache-KB`: Estimated KV-cache footprint in kilobytes (`GQA-8` vs `DeepSeek MLA`).
- `X-Eluvix-PD-Role`: Disaggregated serving role (`prefill`, `decode`, `disaggregated-conductor`, `colocated`).
- `X-Eluvix-TEE-Posture`: Confidential computing posture (`ATTESTED_DUAL_ENCLAVE`, `ATTESTED_CPU_ONLY`, `PLAINTEXT`).
- `X-Eluvix-Quantization-Format`: Upstream weight/activation precision (`nvfp4`, `mxfp4`, `fp8_e4m3`, `int4_awq`, `bf16`).
- `X-Eluvix-Outlier-Rotation`: Active outlier mitigation (`quarot_hadamard`, `spinquant_hadamard`, `svdquant_hadamard_lora`, `none`).
- `X-Eluvix-Tensor-Core-PTX`: Executed Tensor Core instruction (`tcgen05.mma.kind::mxf4nvf4`, `tcgen05.mma.kind::mxf4`, `wgmma.mma_async`).
- `X-Eluvix-Fabric-Topology`: Active GPU cluster fabric (`rail-dlb-oooddp`, `rail-srv6-usid`, `rail-pxn-ecmp`, `tor-static-ecmp`).
- `X-Eluvix-RDMA-Transport`: Active RoCEv2 transport mode (`rocev2-dlb-oooddp`, `rocev2-srv6-usid`, `rocev2-pxn-4qp`, `rocev2-static-ecmp`).
- `X-Eluvix-SRv6-uSID-Carrier`: 128-bit SRv6 Micro-SID carrier address (e.g. `fcbb:bb00:0202:0104:0040::`).
- `X-Eluvix-Cost-USD`: Estimated USD cost recorded in SQLite telemetry for the request.
- `X-Eluvix-Rolling-24h-Spend-USD`: Rolling 24-hour cumulative cloud spend in USD when `maxDailySpendUsd` is active.
- `X-Eluvix-Budget-Fallback`: Set to `local-sovereign` when Switchyard soft-fails over to `\$0` local hardware due to the 24-hour spend ceiling.
- `X-Eluvix-Model-Alias`: Emitted when Switchyard translates a vendor-pinned model string (e.g. `claude-3-5-haiku-20241022` &rarr; `simple`, `claude-3-7-sonnet-20250219` &rarr; `heavy`, `o3-mini` &rarr; `frontier`) into a sovereign capability tier unless `strictModelMatch: true`.
- `X-Eluvix-Cascade`: Speculative cascade decision (`draft-accepted` or `verifier-escalated`) when `speculativeCascade` is enabled.
- `X-Eluvix-Cascade-Confidence`: Measured speculative draft confidence score (`0.00`–`1.00`).
- `X-Eluvix-Embedding-Dimensions`: Vector dimensionality returned by `/api/v1/embeddings` after Matryoshka L2-normalized truncation/padding.
- `X-Eluvix-Cache-Read-Tokens`: Prompt cache read input tokens (discounted by `cacheReadMultiplier`, default 90% discount).
- `X-Eluvix-Cache-Write-Tokens`: Prompt cache creation/write input tokens on Anthropic `cache_control` or prefix-cached upstreams.
- `X-Eluvix-Schema-Validation`: Structured Output JSON Schema validation outcome (`passed`, `repaired`, `escalated`, or `failed`).
- `X-Eluvix-Output-Guard`: Output Guardrail & streaming SSE DLP inspection result (`clean`, `redacted`, or `blocked`).
- `X-Eluvix-Output-Redactions`: Number of secrets, PII tokens, or policy regex matches redacted from the model response.
- `X-Eluvix-Trace-Id`: 128-bit OpenTelemetry trace ID exported via OTLP/HTTP JSON (`gen_ai.*` & `eluvix.*` semantic conventions) or Langfuse.
- `X-Eluvix-Engine-Load`: Live local engine load telemetry (`engine`, `waiting`, `running`, `kv`, `warm`, `delta`).
- `X-Eluvix-Rerank-Model`: Model identifier that scored a `/api/v1/rerank` request.
- `X-Eluvix-Prompt`: Resolved versioned Prompt Registry template (`<id>@v<version>`) when `X-Eluvix-Prompt` or `metadata.promptRef` is supplied.
- `X-Eluvix-Audit-Chain-Valid`: Cryptographic SHA-256 hash-chain verification status (`true` / `false`) on `GET /api/v1/audit?verify=1`.
- `X-Eluvix-Hops`: Incremented hop count returned to the caller.

#### Request Example (cURL)
```bash
curl -k -X POST https://127.0.0.1:3588/api/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $(jq -r .adminPassword ~/.config/eluvix/auth.json)" \
  -d '{
    "model": "auto",
    "messages": [
      { "role": "system", "content": "You are a coding assistant." },
      { "role": "user", "content": "Write a fast matrix multiplication function in C++." }
    ],
    "temperature": 0.2
  }'
```

## 1b. Universal Wire-Protocol Gateway (`/v1/messages`, `/v1/responses`, `/v1/embeddings`)

Eluvix speaks the native wire protocols of Claude Code, Anthropic SDKs, OpenAI Codex CLI, and RAG/vector pipelines directly—applying PrivacyGuard, SemanticGuard, Switchyard complexity routing, and `\$0.00` sovereign tier aliasing across every endpoint.

### `POST /api/v1/messages` (Anthropic Messages Wire Protocol)
Drop-in `ANTHROPIC_BASE_URL=https://127.0.0.1:3588/api` endpoint supporting `x-api-key` and `Authorization: Bearer` headers, top-level `system` blocks, `thinking` (`budget_tokens` &rarr; `<think>` conversion), `tool_use` / `tool_result` blocks, `image` (`base64` / URL) vision blocks, and spec-compliant SSE streaming (`message_start`, `content_block_start`, `content_block_delta` with `thinking_delta` / `text_delta` / `input_json_delta`, `message_delta`, `message_stop`).

### `POST /api/v1/responses`, `GET /api/v1/responses/:id`, `DELETE /api/v1/responses/:id` (OpenAI Stateful Responses API)
Stateful multi-turn orchestration endpoint for Codex CLI and OpenAI Agents SDK:
- Chains multi-turn server-side conversation state via `previous_response_id` persisted in SQLite `response_store` (strictly scoped by `userId`).
- Honors `store: false` for zero-retention confidential turns (never written to `response_store`).
- Streams typed `response.created`, `response.output_text.delta`, `response.function_call_arguments.delta`, and `response.completed` SSE events.

### `POST /api/v1/embeddings` (Matryoshka Dimension-Pinned Embeddings)
OpenAI-compatible vector embedding endpoint routing to local Ollama (`nomic-embed-text`, `bge-m3`), RamaLama, vLLM, or cloud providers:
- Scrubs PII via `PrivacyGuard` prior to embedding generation.
- Enforces **Matryoshka L2-normalized dimension pinning** (`dimensions`) so switching between local and cloud embedding models never breaks downstream pgvector, Qdrant, or SQLite vector table schemas.

## 5. Dataset Fine-Tuning & SFT/DPO Distillation Export

### `GET /api/v1/export`
Exports curated training datasets in JSONL format ready for direct ingestion into Unsloth, Axolotl, TRL, or LLaMA-Factory:

```bash

  -H "Authorization: Bearer <ADMIN_PASSWORD>" \
  -o dpo_preferences.jsonl
```

Records human preference votes from Playground 2.0 A/B Arena (`{ prompt, chosen, rejected, teacherModel, studentModel }`), scrubbing PII through `PrivacyGuard` before writing a `score: 1.0` preference pair to `distillation_pairs`.

## 13. Memory Management API

Memory is always scoped to the authenticated caller (named `elx_` key,
admin bearer, or NextAuth session — see `apps/nextjs/src/lib/caller-identity`).
A `userId` supplied via query string or request body is deliberately
ignored: it can never widen access beyond the caller's own store, and the
response echoes the caller's own `userId`. Readonly callers get `403` on
`POST` and `DELETE`.

### `GET /api/v1/memory`
Retrieves semantically relevant memories or search results for the caller:

#### Query Parameters
- `q` or `query` *(optional)*: Natural language search string. When empty
  or absent, the call lists stored items instead of searching.
- `limit` *(optional)*: Maximum number of memory items to return
  (default: `50`, clamped to `1`–`200`).

With a query and a healthy context provider, the provider's recall runs
first (falling back to local SQLite search when the provider is
unreachable); without a query, stored items are listed.

---

### `POST /api/v1/memory`
Adds a memory item, or commits a session transcript, in the active memory
backend:

#### Add Memory Record (no `action` field)
```json
{
  "content": "Prefers TypeScript strict mode with no implicit any in all repositories.",
  "sessionId": "sess_frontend_123",
  "uri": "memory://user/alice/preferences/1",
  "level": "L1",
  "metadata": { "source": "client" }
}
```

- `content` *(required string)*: anything else returns `400`
  `"'content' string is required"`. There is no `text` field and no
  `category` field — both are ignored if sent.
- `sessionId`, `uri`, `metadata` *(optional)*.
- `level` *(optional)*: `L0`, `L1` (default), or `L2`.
- There is no `action: "add"`: any POST body without `action: "commit"`
  is treated as an add, and the item is also synced to the active
  external provider (OpenViking / Mem0) when one is configured.

#### Commit Session Transcript (`action: "commit"`)
```json
{
  "action": "commit",
  "sessionId": "sess_frontend_123"
}
```

Only `action: "commit"` is special-cased. The provider commits its own
server-side transcript for the session; no `messages` array is read from
the request.

### `DELETE /api/v1/memory`
There is no POST `"clear"` action — clearing is a `DELETE`:

- `DELETE /api/v1/memory?clearAll=true` — deletes all of the caller's
  memories (returns `{ success: true, deletedCount, userId }`).
- `DELETE /api/v1/memory?id=<number>` — deletes a single item, but only
  if it belongs to the caller (returns `{ success: true|false }`).
- Omitting both parameters returns `400` `"Provide '?id=<number>' or
  '?clearAll=true'"`; a non-positive or non-numeric `id` returns `400`
  `"Invalid '?id=<number>' parameter"`.

## 14. Security Audit Chain, Batch API, Reranker, Prompt Registry & Alerting Webhooks (v1.2)

### `GET /api/v1/audit`
Returns tamper-evident security audit events (`api_key.create`, `api_key.revoke`, `config.update`, `prompt.register`, `prompt.promote`). Pass `?verify=1` to walk the entire SHA-256 hash chain (`prev_hash` &rarr; `entry_hash`) from genesis and emit `X-Eluvix-Audit-Chain-Valid: true|false`.

### `POST /api/v1/files`, `GET /api/v1/files`, `GET /api/v1/files/:id/content`
OpenAI-compatible JSONL batch file storage backed by SQLite `batch_files`.

### `POST /api/v1/batches`, `GET /api/v1/batches`, `GET /api/v1/batches/:id`, `POST /api/v1/batches/:id`
OpenAI-compatible asynchronous Batch API executing queued JSONL `/v1/chat/completions` and `/v1/embeddings` items while cooperatively yielding to interactive foreground GPU requests via `CooperativeVramArbiter`.

### `POST /api/v1/rerank`
Cohere / Jina / vLLM compatible cross-encoder and sovereign BM25/overlap reranking endpoint (`{ model, query, documents, top_n, return_documents }`) with `PrivacyGuard` PII scrubbing and `X-Eluvix-Rerank-Model` telemetry.

### `GET /api/v1/prompts`, `POST /api/v1/prompts`
Versioned Prompt Registry storing immutable system templates (`v1, v2, v3...`), aliases (`@staging`, `@production`), and `minEvalScore` promotion gates. Reference prompts in chat requests via `X-Eluvix-Prompt: <id>@production` or `metadata.promptRef`.

### `GET /api/v1/webhooks`, `POST /api/v1/webhooks`, `DELETE /api/v1/webhooks`
Manage and test SSRF-guarded outbound alerting webhooks (`slack`, `discord`, `ntfy`, `json`) signed with `X-Eluvix-Signature: sha256=<hmac_hex>`.

## HTTP Status Codes & Error Handling

| Status Code | Description | Typical Cause |
| :--- | :--- | :--- |
| `200 OK` | Request succeeded. | Successful completion, query, or operation. |
| `400 Bad Request` | Request rejected by Semantic Guard or invalid parameters. | Prompt injection attempt, malformed JSON, or missing required fields. |
| `401 Unauthorized` | Authentication failed. | Missing or invalid master password or named API key Bearer token. |
| `402 Payment Required` | Financial budget cap exceeded. | Request estimated cost exceeds `maxCostPerRequest`. |
| `429 Too Many Requests` | Rate limit or Agent Loop detected. | Sliding-window RPM exceeded, or `x-eluvix-hops` exceeded max threshold (Agent loop detected). |
| `502 Bad Gateway` | Upstream failure. | All candidate engines in the routing queue failed or returned errors. |
| `504 Gateway Timeout` | Execution timeout. | Upstream engine exceeded `timeoutMs` (default 15,000ms). |
