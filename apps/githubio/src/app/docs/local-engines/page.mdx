# Local Engines & Docker Orchestration

Eluvix is built to orchestrate and harness local hardware, providing deep integration with popular local inference engines and container runtimes.

---

## Supported Local Inference & Media Backends

Eluvix connects out-of-the-box with:

1. **Ollama**: Seamless discovery of GGUF models served on `http://127.0.0.1:11434`.
2. **RamaLama**: Rootless OCI container inference via Podman or Docker on `http://127.0.0.1:8080`, supporting `ollama://`, `hf://`, and `oci://` model URIs, `--rag` OCI artifacts, `--selinux=true`, `--network=none` air-gapping, and systemd Podman Quadlet `.container` unit generation.
3. **vLLM**: High-throughput distributed serving with PagedAttention on `http://127.0.0.1:8000` (NVIDIA CUDA or AMD ROCm).
4. **ComfyUI**: Local diffusion, video, and 3D mesh workflow DAG engine on `http://127.0.0.1:8188` (`flux-txt2img`, `sdxl-txt2img`, `wan21-txt2vid`, `hunyuan3d-mesh`).
5. **Speaches (Faster-Whisper) & Kokoro-FastAPI / Piper TTS**: Headless sovereign Speech-to-Text (`http://127.0.0.1:8005`) and Text-to-Speech (`http://127.0.0.1:8880`) audio engines wired via `audioVoiceNode`.
6. **Lemonade**: Local hardware and private NPU/GPU enclave inference runtimes on `http://127.0.0.1:13305`.
7. **OpenViking**: Hierarchical context and memory engine on `http://127.0.0.1:1933`.
8. **TrueForge**: Autonomous agent harness runtime on `http://127.0.0.1:8790`.

## RamaLama Rootless OCI Containers & Quadlets (`:8080`)

When a **RamaLama Node** (`ramalamaNode`) is placed in the **Eluvix Visual Node Routing Editor**, the multi-target compiler generates both exact CLI commands and a production-ready systemd Podman Quadlet (`eluvix-ramalama.container`) for rootless background serving:

```bash
# Serve a local coding model in an air-gapped, SELinux-confined rootless container
ramalama serve --port 8080 --network=none --selinux=true ollama://qwen2.5-coder:7b
```

## ComfyUI Local Media Coexistence & Cooperative GPU VRAM Arbiter

Single-workstation GPUs (`16 GB`–`24 GB` VRAM) frequently run both local LLMs (Ollama `:11434`) and diffusion/video DAGs (ComfyUI `:8188`). In addition to monitoring live GPU memory via `GET /api/v1/comfyui/status`, `@eluvix/router-core` includes a **Cooperative GPU VRAM Arbiter** (`vramArbiter.enabled: true`):

- **Before ComfyUI Synthesis (`media` lease)**: If zero LLM streams are currently in-flight (`activeLlmStreams === 0`), the arbiter inspects SSRF-validated `GET /api/ps` on configured local Ollama endpoints and dispatches `{ model, keep_alive: 0 }` to cleanly unload idle GGUF weights from VRAM before FLUX.1 or Wan 2.1 allocates tensors.
- **Before Local LLM Inference (`llm` lease)**: If zero ComfyUI jobs are active (`activeMediaJobs === 0`), the arbiter dispatches `POST /free` (`{ unload_models: true, free_memory: true }`) to idle ComfyUI endpoints so full VRAM returns to KV-cache and model weights.
- **Zero Container Disruption**: The Cooperative GPU VRAM Arbiter **never stops, kills, or restarts running Docker/Podman containers** and never evicts weights while an active stream or render job holds a lease. Eviction counters (`eluvix_vram_evictions_total`) and active workload gauges (`eluvix_vram_active_workloads`) are exported to `/api/v1/metrics` and `/api/v1/observability`.

## Automated Local Model Discovery

Eluvix includes a discovery API at `/api/v1/detect-models`:

- It actively probes standard local ports (`11434` for Ollama, `8080` for RamaLama, `8000` for vLLM, `8188` for ComfyUI, `1933` for OpenViking, `8790` for TrueForge) with unified SSRF/cloud-metadata protection.
- It queries each engine's model list and tags discovered models with inferred capabilities (`vision`, `code`, `chat`, `image-gen`).
- Discovered models appear automatically as selectable targets in the **Eluvix Visual Node Routing Editor**.

## Containerized Docker Orchestration & Hardware Profiles

Eluvix provides modular Docker Compose overlays to support both NVIDIA CUDA and AMD ROCm GPUs:

### Hardware Overlays

- **NVIDIA CUDA (`docker-compose.nvidia.yml`)**:
  Enables the NVIDIA Container Toolkit runtime with `capabilities: [gpu]` for vLLM.
  ```bash
  docker compose -f docker-compose.yml -f docker-compose.nvidia.yml up -d
  ```

- **AMD ROCm (`docker-compose.amd.yml`)**:
  Enables AMD ROCm 6.2 with direct device passthrough (`/dev/kfd` and `/dev/dri`), mapping your host GFX architecture (e.g. `gfx1100` for Radeon 7900 XTX / 780M, `gfx1030` for 6000-series).
  ```bash
  docker compose -f docker-compose.yml -f docker-compose.amd.yml up -d
  ```

- **CPU Only (`docker-compose.cpu.yml`)**:
  Fall-back configuration for standard CPU execution.
  ```bash
  docker compose -f docker-compose.yml -f docker-compose.cpu.yml up -d
  ```

### Optional Agent Ecosystem Profiles

- **Memory Profile (`--profile memory`)**:
  Spins up the [OpenViking](https://github.com/volcengine/OpenViking) context database container on port `1933`.
- **Harness Profile (`--profile harness`)**:
  Spins up the [TrueForge](https://github.com/truefoundry/trueforge) agent harness runtime container on port `8790`.

Example:
```bash
docker compose -f docker-compose.yml -f docker-compose.amd.yml --profile memory --profile harness up -d
```

## Hardware Auto-Detection Script

The repository includes a hardware auto-detection script at `scripts/docker-detect-and-spinup.sh`:

```bash
chmod +x scripts/docker-detect-and-spinup.sh
./scripts/docker-detect-and-spinup.sh
```

This utility:
1. Detects available GPU hardware: checks `nvidia-smi` and NVIDIA Docker runtime, or inspects `/dev/kfd` and `/sys/module/amdgpu` for AMD ROCm, or falls back to CPU.
2. Identifies GPU architecture (e.g. `gfx1100`, `gfx1030`) and measures available VRAM.
3. Automatically selects and applies the optimal Docker Compose overlay files.
