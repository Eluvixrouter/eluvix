# Desktop Application

The Eluvix Desktop client (located in `apps/desktop`) packages the full Eluvix routing dashboard and orchestration controls into a native desktop window powered by Electron.

---

## Features

- **System Tray Integration**: Run Eluvix in the background with quick access to server logs and status.
- **Full Gateway Parity (`DesktopRouterServer`)**: Complete protocol and security parity with the Next.js web gateway—natively serving `/v1/chat/completions`, Anthropic `/v1/messages` (`x-api-key` & `Bearer` auth), OpenAI stateful `/v1/responses` (`GET`/`DELETE /v1/responses/:id`), Matryoshka `/v1/embeddings`, headless `/v1/audio/transcriptions` & `/v1/audio/speech` (Speaches `:8005` & Kokoro `:8880`), `POST /v1/images/generations` (`comfyui` `:8188`), `POST /v1/mcp` (MCP `2025-06-18`), `POST /v1/evals/run`, `POST /v1/route-explain`, `/v1/observability` (`GET` `dailyRollups` & `DELETE ?olderThanDays=`), `/v1/keys`, `/v1/paperclip/health`, full Paperclip `companyIds`/`maxTier`/`maxCostPer1kUsd`/`x-eluvix-hops` enforcement, `ramalama` (`:8080`), and unified cloud-metadata SSRF protection (`169.254.169.254` / IMDSv2 / Alibaba / IPv4-mapped IPv6).
- **Dedicated Environment**: Isolates your routing console from browser tabs, extensions, and cache conflicts.
- **Local IPC Hooks**: Communicates directly with the local Switchyard core and local filesystem storage.

## Split Desktop Tokens (Chat vs Admin)

The desktop server mints two per-install `0o600` tokens in `~/.config/eluvix/`:

- `desktop-token` is the **chat token** — inference plus read-only discovery only (health, model list, chat completions, embeddings, audio, images, rerank, route-explain, messages, responses, and read-only Paperclip discovery).
- `desktop-admin-token` is the **admin token** — required for config, provider, keys, export, webhooks, MCP, evals, and every other route, and works everywhere.

A chat token presented to an admin route gets `403` ("The chat token cannot access admin routes. Use the admin token."), and unknown routes fail closed as admin-only. The renderer fetches both over IPC and uses the admin token only for admin fetches; the user-facing snippet still shows the chat token.

Provider status and config responses redact secrets (`node_token_configured: true` instead of the value); the settings UI leaves the token field blank with a "leave blank to keep" placeholder and omits an empty token on save, so redaction can never wipe the stored token. `POST /api/config` schema-validates upstreams (`[null]` is rejected with `400`) and deep-merges nested sections. Chat export honors `limit` (default `1000`, max `5000`). Malformed request JSON is `400` at every body-parse site, and failed chat calls are written to the request log. The desktop window runs sandboxed (`sandbox: true`) with `connect-src` allowing `https://127.0.0.1:*` and `https://localhost:*`.

## Development

To run the desktop application in development mode:

```bash
# Ensure router-core and nextjs packages are built
pnpm --filter @eluvix/router-core build

# Compile the desktop app (this only builds — it does not launch anything)
pnpm desktop:build

# Launch the desktop client
pnpm --filter @eluvix/desktop start
```

## Distribution & Packaging

Eluvix uses `electron-builder` to package binaries across multiple platforms:

### Linux
```bash
pnpm --filter @eluvix/desktop run dist:linux
```
Outputs (per `apps/desktop/electron-builder.yml` — there is no `.rpm` target):
- **AppImage** (universal portable Linux executable)
- **.deb** (Debian / Ubuntu package)

### Windows
```bash
pnpm --filter @eluvix/desktop run dist:win
```
Outputs:
- **NSIS Installer** (.exe)
- **Portable .exe**

### macOS
```bash
pnpm --filter @eluvix/desktop run dist:mac
```
Outputs:
- **.dmg** disk image (Apple Silicon and Intel architectures)
