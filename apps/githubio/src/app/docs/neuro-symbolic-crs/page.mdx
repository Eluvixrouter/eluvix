# Neuro-Symbolic CRS Slicing & Sanitizer Verification

Eluvix integrates a defensive **Neuro-Symbolic Cyber Reasoning System (`CRS`)** layer into `@eluvix/router-core` and the Visual Routing Editor (`crsNode`). Rather than sending raw, noisy source files or unverified crash logs to frontier LLMs, Eluvix performs **deterministic backward program slicing**, **exact 64-bit AddressSanitizer (`ASan`/`KASAN`) shadow memory decoding**, **fixed-width bit-vector overflow verification**, and **stall-triggered escalation routing**.

---

## 1. Backward Program Slicing (`def-use` Context Compression)

Frontier reasoning models suffer from severe attention dilution when given thousands of lines of boilerplate code around a suspected vulnerability sink (such as `memcpy`, `strcpy`, or `kfree`). Eluvix's `computeBackwardProgramSlice` function performs an intra-procedural backward `def-use` data-flow walk from the target sink line:

1. **Sink Variable Extraction**: Extracts all identifier tokens referenced at the sink call site (e.g., `memcpy(buf, pkt + 4, payload_len)` extracts `{buf, pkt, payload_len}`).
2. **Transitive Backward Walk**: Walks backward through the function body, retaining only lines that assign to (`def`) a tracked variable or gate control flow (`if`, `while`, `switch`) over a tracked variable, adding newly referenced right-hand-side (`use`) identifiers to the frontier.
3. **Constraint Classification**: Each retained guard is automatically classified for downstream symbolic or LLM reasoning:
   - **`magic-constant`**: Multi-byte protocol magic or checksum equality checks (`magic == 0x504b0304`).
   - **`coupled-arithmetic`**: Multi-variable arithmetic invariants (`total == hdr_len + payload_len`).
   - **`state-guard`**: Protocol state-machine transitions (`state == STATE_AUTH`).
   - **`bounds-check`**: Explicit range or length checks (`len <= MAX_PACKET`).

> **Analytical Derivation**: Compression ratios (`compressionRatio`, `estimatedTokensSaved`) are computed directly from exact line and character counts (`Math.ceil(chars / 4)`) with `derivationMethod: 'analytical-exact'`.

## 2. AddressSanitizer (`ASan` / `KASAN`) Shadow Memory & Hexspeak Triage

When a prompt contains a sanitizer crash log or kernel oops, `computeAsanShadowMapping` and `decodeHexspeakOrPoisonConstant` deterministically compute the exact 64-bit shadow address and decode memory poison tombstones before the LLM generates a root-cause hypothesis:

### Exact Shadow Address Formula (`BigInt`)
Every 8 bytes of application memory map to 1 byte in shadow memory:

```text
ShadowAddr = (FaultAddr >> 3n) + ShadowOffset
```

| Architecture | Shadow Offset (`ShadowOffset`) | Alignment Scale |
| :--- | :--- | :--- |
| **User-space `ASan` (x86_64)** | `0x7fff8000` | `8 bytes -> 1 shadow byte` (`>> 3`) |
| **User-space `ASan` (AArch64)** | `0x1000000000` (`1ULL << 36`) | `8 bytes -> 1 shadow byte` (`>> 3`) |
| **Linux Kernel `KASAN` (x86_64)** | `0xdffffc0000000000` | `8 bytes -> 1 shadow byte` (`>> 3`) |

### Poison Byte & Hexspeak Legend
- **`0x00`**: All 8 bytes in the qword are addressable (`valid`).
- **`0x01..0x07`**: First `k` bytes addressable; remaining `8 - k` bytes out-of-bounds (`partial-sub-qword`).
- **`0xfa`**: Heap left/right redzone (`heap-buffer-overflow`).
- **`0xfd`**: Freed heap region (`heap-use-after-free`, `0xfd` quarantine poison).
- **`0xf1` / `0xf2` / `0xf3`**: Stack left, middle, or right redzone (`stack-buffer-overflow`).
- **`0xf8` / `0xf5`**: `stack-use-after-scope` / `stack-use-after-return`.
- **Hexspeak & Linux SLUB Poison Tombstones**:
  - `0xDEADBEEF`: Uninitialized/freed memory sentinel.
  - `0xFEE1DEAD`: Linux `reboot()` magic / freed lifecycle marker.
  - `0x6b6b6b6b6b6b6b6b`: Linux kernel SLUB `POISON_FREE` (`use-after-free` read/dereference).
  - `0x5a5a5a5a5a5a5a5a`: Linux kernel SLUB `POISON_INUSE` (uninitialized slab allocation).
  - `0xDEAD10CC`: Held lock / deadlock marker.

## 3. Fixed-Width Bit-Vector Overflow Verification & Defensive Patch Synthesis

Standard LLMs frequently assume mathematical integers (`ℤ`) where `a + b > a` for positive values, missing fixed-width modular wrap-around (`mod 2^w`). Eluvix's `verifyBitVectorOverflow` performs exact modular arithmetic over `uint8_t`, `uint16_t`, `uint32_t`, and `uint64_t`:

- **Example (`uint16_t` Allocation Wrap-Around)**:
  - Input: `hdr_len = 16`, `user_len = 65528` (`0xFFF8`) in `uint16_t` (`modulus = 65536`).
  - Mathematical sum: `65544`.
  - Wrapped `uint16_t` allocation size: `(16 + 65528) mod 65536 = 8 bytes`.
  - Subsequent `memcpy(buf, src, 65528)` overflows the 8-byte heap buffer by `65520 bytes` (`ASan` heap redzone `0xfa`).
- **Synthesized Defensive Bounds Check**:
  - **C / C++**: `if (user_len > UINT16_MAX - hdr_len) { return -EINVAL; /* prevent uint16_t wrap-around */ }`
  - **Rust**: `let total = hdr_len.checked_add(user_len).ok_or(Error::IntegerOverflow)?;`

## 4. Switchyard `'stall-escalation'` Strategy & `crsPolicy`

In a neuro-symbolic CRS pipeline, fast local fuzzing/triage tiers handle routine exploration until coverage plateaus (`secondsSinceLastNewPath >= stallThresholdSeconds`, default `300s`) or a complex multi-byte constraint / sanitizer fault is detected:

- **`strategy: 'stall-escalation'`**: Routes routine prompts to `$0` local tiers, automatically escalating to CRS-enabled reasoning/verifier upstreams when a coverage stall (`x-eluvix-crs-stall-seconds`) or sanitizer crash / arithmetic wrap-around is detected.
- **`crsPolicy`**:
  - `'disabled'`: Standard routing.
  - `'slice-and-verify'`: Prioritizes CRS-configured upstreams and injects a deterministic `<eluvix-crs-triage>` pre-computed context block into the system prompt.
  - `'strict-zero-false-positive'`: **Fail-closed** policy that blocks unverified upstreams (HTTP `503` with `x-eluvix-crs-guard: DENIED_CRS_VERIFIER_REQUIRED`) unless a CRS-enabled verifier node is available to validate patches with `ASan`/`UBSan`.

### Telemetry Response Headers
When CRS triage activates on a request, Eluvix emits:
- `x-eluvix-crs-policy`: Active policy (`slice-and-verify` or `strict-zero-false-positive`).
- `x-eluvix-crs-sanitizer`: Decoded sanitizer fault class (e.g., `heap-buffer-overflow (0xfa)`).
- `x-eluvix-crs-shadow-addr`: Exact 64-bit shadow address (`0x10007fff8000`).
- `x-eluvix-crs-bv-overflow`: Fixed-width bit-vector overflow summary (`uint16_t-wrap-to-8`).
- `x-eluvix-crs-slice-ratio`: Backward `def-use` slice compression ratio.
