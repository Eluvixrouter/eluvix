# Rail-Optimized 400G/800G Clos Fabrics (BGP EVPN, SRv6 uSID & DLB)

Standard data center Leaf-Spine (Clos) networks designed for north-south microservice traffic rely on static 5-tuple **Equal-Cost Multi-Path (ECMP)** hashing (`CRC32` / `XOR` of Source IP, Destination IP, Protocol, Source Port, Destination Port). Under distributed AI GPU collective workloads (`NCCL AllReduce` for Tensor Parallelism and `AllToAll` for Mixture-of-Experts), static ECMP suffers catastrophic **hash polarization**—dropping effective 400GbE/800GbE link utilization to **41.0%** (derived from exact Multinomial DP distribution of maximum bin load; empirical cluster measurements ~44.6%) and triggering Priority Flow Control (PFC) pause storms.

Eluvix models, simulates, and orchestrates **Rail-Optimized Plane-Separated Clos Topologies**, **NCCL PxN** intra-node NVSwitch proxying, **RFC 8950 BGP Unnumbered + EVPN** underlays, **128-bit SRv6 Micro-SID (`uSID`)** deterministic Spine pinning, and **Switch Dynamic Load Balancing (DLB)** paired with **ConnectX-7/8 Out-of-Order Direct Data Placement (`OOO-DDP`)**.

## 1. Balls-into-Bins ECMP Hash Polarization Combinatorics

When an 8-GPU node (`M = 8` 400Gbps/800Gbps RoCEv2 NICs) injects synchronized line-rate Queue Pairs ("elephant flows") into a Leaf switch with `K = 8` Spine uplinks under static 5-tuple ECMP, the probability that zero flows collide on any uplink is governed by the classical Balls-into-Bins birthday combinatorics:

```text
P(zero collision) = K! / (K^M * (K - M)!)
For K = 8, M = 8:
P(zero collision) = 8! / 8^8 = 40,320 / 16,777,216 ≈ 0.002403 (0.24%)
P(at least one collision) = 1 - 0.002403 = 99.76%
E[Idle Uplinks] = K * (1 - 1/K)^M = 8 * (7/8)^8 ≈ 2.75 idle Spine uplinks (34.36% wasted capacity)
```

Because a collective step (`AllReduce` or `AllToAll`) cannot complete until its **slowest GPU rank** finishes transferring its shard, a single 2-to-1 or 3-to-1 uplink collision cuts the entire 256-GPU job's throughput in half and fills ingress headroom buffers (`XOFF`), propagating **PFC pause frames** back into innocent senders.

## 2. Rail-Optimized Plane-Separated Clos & NCCL PxN

Rather than wiring all 8 NICs of a server into a single Top-of-Rack (ToR) switch, a **Rail-Optimized** topology separates the cluster into 8 independent planes ("Rails"):
- **NIC `i` of every GPU server** connects to **Rail `i` Leaf Switch** (`i ∈ {0..7}`).
- **Zero-Spine Intra-Rail `AllReduce`**: All GPU Rank `i` NICs across a 32-node (256-GPU) pod sit on the exact same Rail `i` Leaf ASIC, completing ring/tree `AllReduce` in a single **~380ns cut-through hop** without ever traversing the Spine layer.
- **NCCL PxN (`NCCL_PXN_DISABLE=0`, `NCCL_CROSS_NIC=1`)**: When GPU 0 on Node 1 needs to send an MoE `AllToAll` expert dispatch to GPU 3 on Node 18 (Rail 3), crossing rails in the network core would require a 2-tier Spine traversal. With **NCCL PxN**, GPU 0 transfers the payload internally over the node's **900 GB/s NVSwitch** domain to local GPU 3 (NIC 3), which then injects the RoCEv2 packet directly into the **Rail 3 Leaf Switch** (`NCCL_IB_QPS_PER_CONNECTION=4`).

## 3. 128-Bit SRv6 Micro-SID (`uSID`, RFC 8986) Deterministic Spine Pinning

While NCCL PxN + multi-QP entropy raises utilization from `41.0%` to `82.1%`, pseudo-random hashing still leaves a ~15% collision tail during cross-pod collectives. **SRv6 Micro-SIDs (`uSID`, RFC 8986)** allow the host Linux kernel (`iproute2 seg6 mode encap.red`) or SuperNIC to deterministically pin each flow to a disjoint Spine switch with **0 bytes of SRH extension header overhead**:

```text
+-----------------------------------+-------------------+-------------------+-------------------+-------------------+
|       32-bit Locator Block        |   16-bit uSID 1   |   16-bit uSID 2   |   16-bit uSID 3   |  48-bit Zero Pad  |
|            fcbb:bb00              |       0202        |       0104        |       0040        |   0000:0000:0000  |
|   (AI Fabric SRv6 Domain Block)   | (Pin to Spine 02) | (Egress Leaf 04)  | (End.uDT4 VRF 40) |  (End-of-Carrier) |
+-----------------------------------+-------------------+-------------------+-------------------+-------------------+
Full 128-bit IPv6 Destination Address: fcbb:bb00:0202:0104:0040::
```

### 8-Nanosecond Hardware Bit-Shift Pipeline (`End.uN`)
1. **Hop 0 (Ingress Host / Leaf)**: Encapsulates the RoCEv2 packet in an outer IPv6 header (`40 bytes`, saving `56 bytes` vs a legacy 3-SID SRH) with `DA = fcbb:bb00:0202:0104:0040::` and routes via `/48` LPM to **Spine 02**.
2. **Hop 1 (Spine 02 ASIC — `End.uN`)**: Spine 02 matches its local `/48` locator `fcbb:bb00:0202::/48` and executes an **8-nanosecond hardware 16-bit left shift** of bits `32..127`, shifting `0104` into the active uSID slot (`DA = fcbb:bb00:0104:0040::`) and forwarding to **Egress Leaf 04**.
3. **Hop 2 (Egress Leaf 04 — `End.uDT4`)**: Egress Leaf 04 pops the outer IPv6 header (`fcbb:bb00:0040::`), performs a VRF `0040` tenant lookup, and delivers the inner RoCEv2 frame to the target GPU NIC.

## 4. Switch DLB & ConnectX-7/8 Out-of-Order Direct Data Placement (`OOO-DDP`)

For dynamic Mixture-of-Experts (`AllToAll`) token routing where expert loads skew unpredictably every millisecond, **Dynamic Load Balancing (DLB)** on Broadcom Tomahawk 5 / NVIDIA Spectrum-4 ASICs sprays individual packets across whichever Spine port has the lowest real-time egress queue depth (`< 200ns` telemetry).

Traditionally, packet spraying broke RDMA because out-of-order Packet Sequence Numbers (`PSN`) triggered InfiniBand **Go-Back-N NAKs**. NVIDIA **ConnectX-7 / ConnectX-8 SuperNICs** solve this in silicon via **Out-of-Order Direct Data Placement (`OOO-DDP`)**:
- Every `RDMA WRITE` / `SEND` carries a 24-bit `PSN` inside the 12-byte InfiniBand Base Transport Header (`BTH`).
- Since the Queue Pair's Path MTU (`4096 bytes`) and base GPU HBM3e Virtual Address (`VA`) are registered in the NIC's Memory Translation Table (`MTT`), the SuperNIC computes the exact target byte offset for **any** arriving packet:
  ```text
  targetHbmOffset = baseAddress + (PSN - basePsn) * 4096
  ```
- The NIC DMA-writes `PSN 1003` and `PSN 1002` directly into their exact GPU HBM3e locations as they arrive, tracks arrivals in a hardware **Sliding PSN Bitmap Window** (`OO_RECV_WR_EN=1`, `ROCE_ADAPTIVE_ROUTING_EN=1`), and posts the Completion Queue Entry (`CQE`) to the GPU the instant missing `PSN 1001` lands—delivering **zero retransmissions** and **97.8% line-rate utilization**.

## 6. Fabric-Aware Switchyard Routing & Telemetry Headers

In the Visual Routing Editor (`/editor`) or `RouterConfig`, configure `fabricPolicy` on the **Switchyard Node**:
- **`disabled`**: Standard routing without fabric topology filtering.
- **`prefer-rail-optimized`**: Ranks collision-free Rail-Optimized workers (`rail-dlb-oooddp` > `rail-srv6-usid` > `rail-pxn-ecmp`) ahead of legacy ToR static ECMP workers.
- **`require-collision-free-fabric`**: Fails closed (excluding `tor-static-ecmp` upstreams) so distributed MoE and long-context collective workloads never land on hash-polarized ToR switches.

```bash
curl https://127.0.0.1:3588/api/v1/chat/completions \
  -H "Authorization: Bearer $ELUVIX_API_KEY" \
  -H "Content-Type: application/json" \
  -H "x-eluvix-fabric: require-collision-free-fabric" \
  -d '{
    "model": "deepseek-ai/DeepSeek-V3",
    "messages": [{"role": "user", "content": "Execute distributed MoE AllToAll synthesis..."}]
  }'
```

Every response from a fabric-configured upstream emits:
- `x-eluvix-fabric-topology`: `rail-dlb-oooddp` | `rail-srv6-usid` | `rail-pxn-ecmp` | `tor-static-ecmp`
- `x-eluvix-rdma-transport`: `rocev2-dlb-oooddp` | `rocev2-srv6-usid` | `rocev2-pxn-4qp` | `rocev2-static-ecmp`
- `x-eluvix-srv6-usid-carrier`: Active 128-bit SRv6 uSID carrier address (e.g. `fcbb:bb00:0202:0104:0040::`)
