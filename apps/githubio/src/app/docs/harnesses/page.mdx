# Agent Harnesses & Runtimes

Eluvix is engineered to bridge traditional reactive LLM routing with autonomous, multi-turn **Agent Harnesses**. While standard routers simply process stateless prompt-completion cycles, an Agent Harness manages stateful execution loops, tool call dispatching, permission validation, and sub-agent orchestration.

---

## What is an Agent Harness?

In modern AI agent architectures, an **Agent Harness** (or agent runtime) wraps an underlying model with:
1. **Execution Loop**: Continually alternates between model reasoning and tool execution until a task is finalized.
2. **Tool Sandboxing & Execution**: Spawns isolated processes (bash, python, git, web browsers) or communicates with MCP servers.
3. **Approval Interception**: Holds execution when an agent attempts destructive or sensitive actions (e.g., file writes, shell execution, external network calls).
4. **State Persistence**: Maintains conversation history, working memory, and intermediate tool outputs across turns.

Eluvix acts as both an **intelligent LLM upstream provider** to external harnesses and a **direct proxy orchestrator** that can route incoming user tasks directly into autonomous agent engines.

## 1. TrueForge Deep Dive

[TrueForge](https://github.com/truefoundry/trueforge) is a modular, high-performance agent runtime designed by TrueFoundry for multi-step agent execution with granular tool approvals.

### Architecture & Turn-Based Execution

TrueForge operates using a **Session and Turn** model:
1. **Session Initialization**: A session is created with a designated agent configuration, environment variables, and tool registry.
2. **Turn Execution**: The client posts a user prompt to initiate a turn. TrueForge streams the agent's thoughts, proposed tool calls, and execution steps over Server-Sent Events (SSE).
3. **Tool Approval Loop**: When a tool requires approval, the turn suspends until an approval or rejection event is dispatched.

```text
Client / Router ──► POST /api/v1/sessions ──► Session ID
       │
       ▼
POST /api/v1/sessions/{id}/turns (Prompt)
       │
       ▼ (SSE Stream: turn.start, step.start, tool.call)
[ Tool Call Triggered ]
       │
       ├──► Auto-Approve Readonly? ──► Execute tool & stream result
       │
       └──► Write / Exec Tool? ─────► Suspend & wait for approval
                                              │
       POST /api/v1/sessions/{id}/turns/{turnId}/events ◄───┘
       {"type": "tool_approved", "call_id": "call_123"}
                                              │
                                              ▼
                                   Resume execution loop
```

### Headless Tool Approval Policies

When running TrueForge in headless or automated environments (e.g. CI/CD or backend gateways), Eluvix enforces configurable approval policies:

- **`auto-approve-readonly` (Default)**: Automatically permits safe inspection operations (e.g., `read_file`, `grep_search`, `list_directory`, `git_status`) without user friction, while pausing or alerting on write/delete/execute tools.
- **`auto-deny`**: Immediately denies any tool action requiring approval, ensuring unattended safety in zero-trust environments.
- **`surface`**: Suspends the turn and surfaces the permission request over SSE to the client or dashboard for interactive operator approval.

### Docker Deployment

To launch TrueForge alongside Eluvix using Docker Compose:

```bash
docker compose --profile harness up -d
```

TrueForge binds to port `8790` and is immediately discoverable by Eluvix.

## 2. Eluvix-Forked OpenCode (`@eluvix/opencode-harness`) & In-Process TrueForge

In addition to connecting to external OpenCode (`:4096`) and TrueForge (`:8790`) servers, Eluvix ships with an embedded in-process TrueForge loop and **`@eluvix/opencode-harness`** (`packages/opencode-eluvix`), which intercepts every intermediate agent step inside the execution loop:

- **Mid-Loop DLP (Privacy Guard on Tool Outputs)**: Before raw `bash` or `read_file` outputs re-enter the LLM context window, Eluvix scrubs leaked secrets, `.env` keys, and PII so private tokens never reach cloud models on subsequent turns.
- **Indirect Prompt Injection Scanning**: Scans external files and web tool outputs through `PromptGuard` before the agent's next reasoning step.
- **Switchyard Dynamic Step Tiering**: Automatically routes architectural planning steps (`step 0`) to frontier reasoning models, routine file inspection / `grep` steps to `$0` local coding models, and final patch synthesis to high-capability coders.
- **KV-Cache Prefix Pinning**: Computes a deterministic SHA-256 prefix hash across the session's system instructions and tool definitions so vLLM and SGLang workers keep the session's PagedAttention / RadixAttention KV blocks warm across all turns.
- **Unified Agent Harness Studio (`/harness`)**: Inspect live multi-turn trajectories, approve or reject suspended tool calls, and switch between all 8 harness adapters in real time.

## 3. Agent Client Protocol (ACP)

The **Agent Client Protocol (ACP)** is a JSON-RPC 2.0 standardized protocol designed for bidirectional agent-to-editor communication:

### Protocol Handshake & Flow

1. **Initialization (`initialize`)**:
   ```json
   {
     "jsonrpc": "2.0",
     "id": 1,
     "method": "initialize",
     "params": {
       "protocolVersion": "1.0",
       "clientInfo": { "name": "eluvix-router", "version": "1.0.4" }
     }
   }
   ```
2. **Session Creation (`session/new`)**: Binds working directory and capabilities.
3. **Turn Execution (`session/prompt`)**: Streams response deltas and tool invocation blocks.
4. **Permission Negotiation (`session/request_permission`)**: Interactive permission requests for disk and network operations.

Eluvix provides built-in stdio process spawning and stream demuxing for any ACP-compliant agent binary.

## 4. Loop Prevention & Hop Guard (`x-eluvix-hops`)

One of the most dangerous failure modes in multi-agent and harness systems is the **Infinite Agent Loop**:
- Agent *A* uses Eluvix as its LLM backend.
- Agent *A* invokes a tool that queries Agent *B*.
- Agent *B* queries Eluvix, which inadvertently routes back to Agent *A*.
- The loop cascades recursively, burning millions of tokens and exhausting compute in seconds.

### The Eluvix Loop Guard

Eluvix introduces a mandatory **Loop Guard** pipeline stage:

```text
Incoming Request ──► Check Origin & Headers
                           │
                           ├── Origin: "client" ──► Hop Count = 0 (Allow)
                           │
                           └── Origin: "harness" ─► Inspect `x-eluvix-hops`
                                                         │
                                    ┌────────────────────┴────────────────────┐
                                    ▼                                         ▼
                             Hops < Threshold                          Hops >= Threshold
                            Increment: Hops + 1                     REJECT: HTTP 429 Loop Detected
                             Forward to Router                       "Agent recursion limit exceeded"
```

1. **Named Key Origin**: API keys in `keys.json` can be assigned `origin: "harness"`.
2. **Hop Counter**: Requests originating from or passing through a harness increment the `x-eluvix-hops` HTTP header.
3. **Threshold Rejection**: If `x-eluvix-hops` reaches or exceeds the configured limit (default: `2`), Eluvix rejects the call with an HTTP `429` status code and an explicit diagnostic payload:
   ```json
   {
     "error": {
       "message": "Potential agent routing loop detected: hop count (2) exceeds maximum allowed threshold (2).",
       "type": "loop_detected_error",
       "code": "agent_recursion_limit_exceeded"
     }
   }
   ```

## 5. Visual Editor Configuration (`HarnessNode`)

In the Eluvix Visual Routing Editor (`/editor`), you can add and wire a **Harness Node**:

1. Open `/editor`.
2. Drag **Agent Harness** from the left node palette onto the canvas.
3. Select the runtime:
   - `trueforge` (Port 8790)
   - `opencode` (Port 4096)
   - `acp` (Stdio JSON-RPC)
   - `hermes` (Port 8080)
4. Configure the **Tool Approval Policy** (`auto-approve-readonly`, `auto-deny`, `surface`).
5. Set the **Max Hops Limit** (`1` to `5`).
6. Connect the harness node to an upstream model or intent port. When compiled, the router automatically applies loop guarding and turn orchestration.
