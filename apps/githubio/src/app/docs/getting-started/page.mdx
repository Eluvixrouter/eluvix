# Getting Started

Welcome to **Eluvix**, an intelligent, privacy-first, multimodal LLM routing gateway and orchestration dashboard. Eluvix unifies your local hardware (Ollama, vLLM, Lemonade) and frontier cloud models (OpenAI, Anthropic) into a single resilient, OpenAI-compatible endpoint.

---

## Prerequisites

Before setting up Eluvix, ensure your environment meets the following requirements:

- **Node.js**: `v22.13.0+` (LTS recommended, required for built-in `node:sqlite`)
- **pnpm**: `v11.0.0+` (`pnpm@11.24.0` is configured in `package.json`)
- **mkcert** *(Recommended)*: For automated local TLS certificate generation
- **Docker & Docker Compose** *(Optional)*: For production deployments and containerized local model engines
- **Git**

## Quickstart (Local Development)

### 1. Clone Repository & Install Dependencies

```bash
git clone https://github.com/Eluvixrouter/eluvix.git
cd eluvix

# Install workspace dependencies
pnpm install
```

### 2. Configure Environment (Optional)

Eluvix is zero-config by default. On its first boot, it automatically generates a secure 24-letter random admin password and a NextAuth session secret, storing them in `~/.config/eluvix/auth.json`.

If you prefer to define credentials manually, create a `.env` file in the root or `apps/nextjs`:

```bash
cp .env.example .env
```

Available environment variables:

| Variable | Description | Default |
| :--- | :--- | :--- |
| `ADMIN_PASSWORD` | Master password for console login and API authentication | Auto-generated in `~/.config/eluvix/auth.json` |
| `NEXTAUTH_SECRET` | Secret key used to encrypt session JWT tokens | Auto-generated in `~/.config/eluvix/auth.json` |
| `NEXTAUTH_URL` | Canonical URL for NextAuth callbacks | Auto-detected from host and port |
| `PORT` | HTTPS port for the Next.js server (same-port dual-protocol demux; see the note under §3 — only browser navigation is 308-upgraded, `/api/` is served over plain HTTP) | `3588` |
| `HTTP_PORT` | Optional secondary HTTP redirect port | `3580` |
| `HOSTNAME` | Listening network interface | `127.0.0.1` |

### 3. Launch Development Server

```bash
pnpm dev
```

During startup:
- `@eluvix/router-core` is compiled.
- If `mkcert` is installed, a trusted local TLS certificate is issued for `localhost`, `127.0.0.1`, and `eluvix.local`.
- If credentials do not yet exist, a fresh admin password is generated and printed in your terminal.
- **Same-Port Dual-Protocol Demuxing on Port 3588**:
  - The server binds port `3588`.
  - Encrypted clients connect via `https://127.0.0.1:3588`.
  - Plaintext HTTP **browser navigation** to `http://127.0.0.1:3588` is upgraded via `HTTP/1.1 308 Permanent Redirect` to HTTPS on the exact same port — but **API requests are not**: `/api/` paths on port 3588 are served directly over plain HTTP by design (`apps/nextjs/server.mjs`: the HTTP handler serves `/api/` before the 308 branch). API clients must use `https://127.0.0.1:3588/api/v1`.
  - An optional secondary redirect server also runs on `http://127.0.0.1:3580`.

> **Security note:** never send an `Authorization: Bearer` admin password or
> named API key to `http://127.0.0.1:3588/api/...` — it will work, and it
> will travel unencrypted. Always use the `https://` URL for API traffic.
> For trusted local TLS, install `mkcert` before first boot (see above) so
> the server can issue a certificate for `localhost`, `127.0.0.1`, and
> `eluvix.local`; without it the server falls back to plain HTTP.

Open your browser to `https://127.0.0.1:3588` (or simply `http://127.0.0.1:3588`) and sign in using the password printed in your console or found in `~/.config/eluvix/auth.json`.

## Production Deployment (Docker)

Eluvix provides modular Docker Compose configurations tailored for specific hardware:

### Hardware-Accelerated Deployments

```bash
# NVIDIA CUDA (vLLM with GPU passthrough)
docker compose -f docker-compose.yml -f docker-compose.nvidia.yml up -d --build

# AMD ROCm (ROCm 6.2 with /dev/kfd and /dev/dri passthrough)
docker compose -f docker-compose.yml -f docker-compose.amd.yml up -d --build

# CPU Only (Ollama + CPU inference)
docker compose -f docker-compose.yml -f docker-compose.cpu.yml up -d --build
```

### Agent Harnesses & Memory Engine Profiles

Eluvix includes optional Docker Compose profiles for dedicated agent backends:

```bash
# Spin up with OpenViking Hierarchical Memory Engine (:1933)
docker compose --profile memory up -d

# Spin up with TrueForge Agent Runtime (:8790)
docker compose --profile harnesses up -d

# Launch entire sovereign agent stack (Router + OpenViking + TrueForge + vLLM)
docker compose --profile memory --profile harnesses up -d
```

## Hardware Auto-Detection & Helper Scripts

### 1. Hardware Detection & Docker Spinup
To automatically detect your GPU vendor (NVIDIA CUDA, AMD ROCm, Apple Silicon, or CPU) and boot the optimal compose stack:

```bash
chmod +x scripts/docker-detect-and-spinup.sh
./scripts/docker-detect-and-spinup.sh
```

This utility detects whether NVIDIA Container Toolkit or AMD ROCm (`/dev/kfd`) is accessible, determines your GPU architecture (e.g. `gfx1100`, `gfx1030`), measures available VRAM, and boots the matching container configuration.

### 2. Antigravity Agent CLI (`agy`)
Eluvix can route to Google's **Antigravity CLI** (`agy`) as an agent upstream. Eluvix does not ship an installer for it: install `agy` using Google's official Antigravity installer and documentation, and keep it updated through Google's own update channel. (Eluvix previously bundled a third-party bootstrapper script for this; it was removed — a download-and-execute script is only as trustworthy as whoever serves the download, so get the CLI from the vendor.)

Once installed, make sure `agy` is on your `PATH` — Eluvix looks in `~/.local/bin`, `~/bin`, `/usr/local/bin`, and `/usr/bin`, in addition to the `PATH` — or set the upstream's **CLI Path** explicitly in the layout editor. Eluvix validates that path before use.

## Desktop Application

Eluvix includes a native cross-platform desktop application built with Electron:

```bash
# Build desktop assets
pnpm desktop:build

# Package for your local operating system (Linux AppImage/deb, Windows exe, macOS dmg)
pnpm desktop:dist
```

For more details, see the [Desktop Application Guide](/docs/desktop).
